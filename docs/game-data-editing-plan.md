# 游戏数据修改技术方案

研究日期：2026-09-18；对应版本：v0.3.6。

## 本次交付与结论

本次只实现游戏页的反作弊进程提示，不实现游戏数据读取、扫描、写入或修改入口。本文后续模块和界面均为设计提案，尚未交付。

建议采用「按游戏与版本适配的修改项」，先支持一款明确的单机游戏和一个基础数值。用户绑定游戏后看到生命、资源等命名修改项，而不是每次手动搜索地址。优先选择游戏官方支持的配置、控制台或 Mod 接口；无此接口时，再按具体游戏评估存档和内存方式。

**没有发现反作弊进程，不等于没有反作弊，也不等于数据可以修改。** BattlEye 官方资料说明其涉及服务与内核驱动，单纯的普通进程列表不能覆盖全部保护方式。[BattlEye FAQ](https://www.battleye.com/support/faq/)

## 1. 已实现的状态标识

位置：游戏页进程名下方，与「运行中 / 已暂停」同一行。标签约 12px，圆角、小面积底色，不挤占暂停／恢复主按钮。

| 状态 | 标识 | 含义 |
| --- | --- | --- |
| 尚未完成或结果超过 6 秒 | 灰色「反作弊：检测中」 | 等待新快照，不沿用过期结论 |
| 已知名称命中 | 金色「发现反作弊进程」 | 系统中存在匹配名称，不代表已确认属于当前游戏 |
| 完整枚举成功、无匹配 | 绿色「未发现已知进程*」 | 只表达有限名单没有命中，不显示「可修改」承诺 |
| 枚举失败或快照为空 | 金色「反作弊：未知」 | 错误不当作无反作弊，自动重试 |
| 未绑定／游戏已退出 | 不显示检测标识 | 不给没有目标的修改结论 |

悬停显示命中名称、检测范围与限制。检查每 2 秒执行一次，有绑定时才扫描；切换绑定会清空结果。绑定代数校验防止旧扫描结果写入新会话，进程退出后不接受结果。结果只驻留内存，不保存到配置文件。

初始规则为可执行文件名的完整匹配，忽略大小写：

| 可执行文件名 | 提示类别 |
| --- | --- |
| `BEService.exe` | BattlEye |
| `BEService_x64.exe` | BattlEye |
| `EasyAntiCheat.exe` | Easy Anti-Cheat |
| `EasyAntiCheat_EOS.exe` | Easy Anti-Cheat EOS |

这是有限名称表，不是反作弊产品完整数据库；名称可以变化或被仿冒。目前不校验文件签名，不枚举内核驱动、服务状态、游戏模块，也不识别内置或服务端保护。其他游戏的反作弊后台进程也会触发提示。安装器名称不会作为运行中的反作弊服务命中。[BattlEye 文件名说明](https://www.ubisoft.com/en-us/game/rainbow-six/siege/news-updates/2999gdyIXLbeiZP78R7545/battleye-faq)、[Epic 安装说明](https://www.epicgames.com/help/c-37371353/a20611857?lang=en-US)

实现使用 Tool Help 的系统进程快照，枚举名称后立即释放快照句柄，不对这些进程申请暂停或读写权限。现有 `process::enumerate()` 只返回可打开暂停句柄的进程，会过滤部分进程，因此不能作为检测数据源。[Microsoft 系统快照说明](https://learn.microsoft.com/en-us/windows/win32/toolhelp/snapshots-of-the-system)

后续若扩展检测，建议增加只读服务／驱动状态、可信文件路径与签名核验，并区分「当前游戏关联证据」和「系统其他进程提示」。即使扩展，也不能把没有命中作为允许写入的唯一条件。

## 2. 修改方式选择

下表是工程取舍，不是对任意游戏兼容性的承诺。

| 方式 | 使用体验 | 开发与维护成本 | 建议 |
| --- | --- | --- | --- |
| 游戏官方配置／控制台／Mod API | 命名选项、数值输入；通常较稳定 | 依赖各游戏支持的接口 | 第一优先；按游戏文档适配 |
| 本地存档编辑 | 退出游戏后选存档、修改、备份恢复 | 格式、校验和、压缩与云存档冲突需逐个处理 | 已知格式的单机游戏适用 |
| 进程内存数据修改 | 运行中读取当前值并修改 | 地址动态变化、版本更新、指针生命周期、权限与竞争问题 | 第一期内存功能只做已验证适配 |
| 通用数值搜索 | 输入当前值、多次缩小候选、人工确认 | 类型识别、误命中、性能、地址失效与交互复杂 | 后续高级工具，不作为初版主流程 |

内存方案不能自然修改服务器权威数据。界面上的数字可能只是缓存、显示副本或经编码的值；不能凭搜索命中就认定找到了游戏逻辑中的真实字段。

## 3. 未来的用户流程

1. 在现有游戏页绑定游戏，查看反作弊提示。
2. 后台只读识别可执行路径、架构、版本和文件指纹，匹配本地适配配置。
3. 适配成功后才出现小型「数据修改」入口；打开独立面板，避免挤占当前小组件。
4. 面板显示「当前值 → 目标值」、允许范围、适配版本与读取状态。
5. 用户点击应用后执行一次修改，再读回核对；失败明确指出原因，不自动反复尝试写入。
6. 同会话可提供有条件的撤销；游戏退出、版本变化或地址失效后撤销不可用。

未来「可修改」需同时满足：有匹配且验证过的适配器、目标为该适配支持的本地模式、检测没有阻止条件、身份与地址验证通过、必要访问权限可用。只检测进程名不满足这些条件。无法确认联网／离线模式时，适配器应明确限制支持模式，不能用「没有网络连接」自动推断单机。

第一期不做自动冻结、无限值、脚本执行或启动即写入。数据修改和按键宏是不同模块，不共用执行逻辑。遇到反作弊或保护限制时停止修改流程，本方案不包含停用、绕过或注入保护组件的实现。

## 4. 与现有 Rust 项目的接入

已实现：

- `src/anti_cheat.rs`：独立快照、名称规则、检测结果和有效期。
- `AppState`：绑定代数与检测报告；切换游戏时作废报告。
- `src/main.rs`：后台检测线程、游戏页小标识与悬停解释。

拟新增模块（本次不创建功能代码）：

| 模块 | 职责 |
| --- | --- |
| `game_identity` | 路径、创建时间、架构、版本／哈希；防止 PID 重用和同名游戏混淆 |
| `game_profiles` | 适配器配置、支持版本、字段类型、范围、定位方式、预期数据约束 |
| `edit_session` | 会话状态、后台任务、取消、权限生命周期、版本校验、结果回传 |
| `memory_backend` | 封装有限范围的读取、区域检查、数据写入与读回校验 |
| `save_backend` | 存档格式解析、备份、变更预览、替换与恢复 |
| `edit_panel` | 命名字段、当前值、输入、应用和撤销 |

保留现有暂停句柄职责，另行按需申请内存权限，不把进程列表全部改为请求 `PROCESS_ALL_ACCESS`。后台扫描／读写不持有全局 UI 锁，结果携带绑定代数，只交给仍然有效的会话。切换、解除绑定、退出时取消任务，并等待正在执行的操作结束后再销毁会话。

Windows 内存读取需 `PROCESS_VM_READ`；写入需 `PROCESS_VM_WRITE | PROCESS_VM_OPERATION`；区域查询需 `PROCESS_QUERY_INFORMATION`。权限拒绝是正常错误状态，不默认提权。[读取 API](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-readprocessmemory)、[写入 API](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-writeprocessmemory)、[区域查询 API](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualqueryex)

## 5. 游戏适配配置

圆点配置继续按进程名保存；**数据修改适配不能只按进程名或 PID 匹配**。不同游戏可能同名，同一游戏更新后内存布局可能变化。

建议未来独立目录 `%APPDATA%\SlackInput\edit-profiles\`，与 `games` 中的圆点配置隔离。每份适配配置至少包含：

- schema 版本、游戏 ID、适配器版本、支持的游戏模式；
- 可执行文件名、架构、已验证版本和文件指纹；
- 字段 ID、显示名、类型（初期 `i32/u32/f32`）、单位、范围；
- 模块相对偏移／受限指针链、预期结构和值域校验；
- 允许读写的字段清单、是否支持撤销、来源与验证日期。

先使用模块基址加偏移和受限指针链，禁止把上次的绝对地址持久化后直接复用。按版本精确匹配，不匹配就禁用该适配。特征匹配可作为后续增强，但必须限定模块／区域、验证唯一匹配和目标语义，不能把一次字节匹配当作版本兼容证明。

这些配置应该是声明式数据，不能加载任意脚本或 DLL。用户保存的是字段偏好，不是开机后自动恢复写入的任务。

## 6. 一次内存修改的执行约束

1. 固定会话身份和进程句柄，检查目标仍存活、适配版本相符，重新确认检测状态未过期。
2. 解析地址并用 `VirtualQueryEx` 校验区域边界、状态与可访问属性；限制指针链深度和读取大小。
3. 读取原值，验证类型、合法范围和预期值；写入前再核对目标地址与原值。
4. 只向适配允许的数据字段写入固定长度值；核对返回值和实际写入字节数，再读回。
5. 记录会话内的原值、写入值、地址与时间；撤销前重新验证身份和地址，并要求当前值仍等于本工具写入值。

Windows API 的读写检查不是与游戏逻辑共享的原子事务，步骤之间仍可能竞争。不能保证暂停进程后就获得游戏语义上的一致状态，也不能承诺所有修改都可撤销。适配器需选择稳定字段；验证失败停止该操作，不在地址变化后盲目补写。初期不写代码页、不改变页面保护、不注入代码。

存档方案另外要求：确认游戏未运行、验证文件身份和格式、先创建带时间戳备份、写入临时文件并重读校验、使用适合文件系统的替换方式。云同步冲突需要显示差异，不能静默覆盖新存档。

## 7. 开发阶段与验收

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| 当前 v0.3.6 | 只读进程提示与本方案 | 正确区分命中／未命中／错误／过期；切换会话不串结果 |
| 下一阶段 A | 指定一款游戏与一个字段，只读适配 | 多次启动定位稳定；版本不匹配和退出能停止读取 |
| 下一阶段 B | 单次修改、读回和条件撤销 | 对自建测试程序验证成功、权限拒绝、短读写、地址失效、竞争和撤销冲突 |
| 后续 C | 更多游戏、存档适配、可选搜索器 | 每款游戏独立版本矩阵；限制扫描资源并支持取消 |

本次测试：规则大小写与去重、相似名称不误命中、空快照与错误不显示未发现、报告过期、跨绑定会话拒绝结果，以及真实 Windows 快照包含本进程。已有暂停、恢复、托盘、圆点与配置测试继续运行。截图检查只用 UI 示例，不启动或操作真实游戏。

未来数据修改测试应先使用自建子进程和固定内存字段，不能拿当前运行的游戏做自动化写入测试。额外覆盖：32/64 位差异、进程退出及 PID 重用、游戏更新、页边界、权限失败、非有限浮点值、超范围输入、备份失败和云存档冲突。只有适配器在目标游戏版本上通过人工验证后才标记支持。

## 8. 后续实施所需信息

需要指定第一款游戏、平台（例如 Steam / Xbox PC）、可执行文件名与版本、希望修改的具体字段，以及使用单机／离线模式的情况。拿到这些信息才能确定它适合官方接口、存档还是内存方式，并估计适配成本；目前不能给出通用修改成功率。
