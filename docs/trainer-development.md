# 修改器模块开发交接（v0.5.0）

> 本文是 v0.5.0 交接记录。后续已实现 EXE 导入界面、名称冲突处理、单项删除及执行因子配置化；当前行为与配置说明见 [修改器管理方案](trainer-management-plan.md)。下文关于“没有导入按钮”、内置优先和配置必须完全一致的描述已被新方案替代。

## 当前交付与边界

游戏页在「解除绑定」旁新增「修改器」按钮，打开独立窗口。未绑定时可以预览内置列表；绑定 `Digimon Story Time Stranger.exe` 后自动加载对应配置。进程名匹配不区分大小写。

界面包含 40 项功能，分为战斗与探索、资源与物品、数码宝贝属性，支持搜索、仅启用筛选、启用/停用、数值输入、应用和停用全部。「仅启用」按当前实际启用状态筛选，可与搜索叠加；一次性应用记录不计为持续启用。原样本的游戏速度、移动速度两项已经排除。

**40 项均已接入原生执行后端**，其中 27 项持续开关或数值修改、13 项一次性属性编辑。它们已通过自建数据上的机器码执行、扫描安装、共享参数和恢复测试；真实游戏效果尚未验证。来源文件标注的版本范围不能当作本程序已验证的游戏版本范围。

金钱和点数暂支持 `1..=2147483647` 的整数，默认值来自样本定义。启用后在游戏执行对应逻辑时写入；“已启用”说明适配代码和参数安装成功，不表示已经读到游戏画面上的新值。停用不会回退已经获得的资源，输入 0 不用于关闭功能。

倍率支持 `0.01..=1000` 的有限小数，写入 f32 参数；整数奖励/伤害乘除结果限制在 i32 范围。经验倍率在奖励结算逻辑执行时生效，与「无限经验」同时启用时后者优先。

属性编辑流程：首次点击「应用」安装读取钩子 → 在游戏中打开或重新打开目标数码宝贝属性界面 → 再点击「应用」 → 重开属性界面刷新显示。首次点击不会排队等待未来对象，也不会标为已写入。每次写入都会在暂停期间校验捕获地址和对象 ID，拒绝失效对象；界面记录上次成功应用的数值和 ID。停用全部不撤销已经写入的属性。

关闭修改器窗口会保留当前修改；停用全部、切换绑定、解除绑定和正常退出程序会尝试恢复修改。恢复失败时保留旧会话和句柄、展示错误并阻止新修改，用户可重试「停用全部」。游戏退出后清空状态。强制结束程序不提供恢复保证。

## 已预留的导入接口

后续导入按钮按以下接口接入，无需让窗口承担静态分析或进程操作：

1. `StaticImporter::analyze(&[u8]) -> Result<ImportDraft, String>`：分析文件，输出配置和警告，不启动 EXE、不加载 DLL、不执行脚本。
2. `ImportDraft { profile, warnings }`：供未来导入预览展示；元数据提取与执行适配能力需分别报告。
3. `Repository::install(&ImportDraft)`：校验后写临时文件、同步并改名，已存在同 ID 时返回错误，不隐式覆盖。
4. `Repository::resolve(process_name)`：按进程名加载配置。主程序在绑定时调用，重启后重新绑定同名进程会重新加载；不恢复任何启用状态。

当前 `SampleImporter` **只是已知样本识别器**：核验 MZ、32 MiB 上限和完整 SHA-256 后返回内置的已提取配置，不是通用 EXE 数据提取器。未知文件或修改过的文件返回不支持。没有在界面增加尚未完成的通用导入按钮。

已知样本 SHA-256：

```text
655f340b386aa82d4e41c84fd6c9f434cdad2a3b6d761dbf81ba09359d0e7e84
```

该哈希识别的是来源修改器，**不是游戏 EXE 的版本哈希**。

内置配置 ID 为 `digimon-time-stranger-20260709`。该 ID 的元数据必须与内置定义完全一致，避免通过 JSON 修改进程名或字段来调用既有执行器。其他配置可以加载和展示，但不会自动获得内存写入能力。`supported(profile, feature_id)` 是当前适配白名单，后续应演进为注册式适配器能力查询。

## 配置存储与数据结构

外部配置目录：`%APPDATA%\SlackInput\trainers\`，每个修改器一个 `{id}.json`。它与通用设置以及 `games` 下的圆点设置独立。内置游戏配置直接编译进程序，运行时不依赖 dist 中的来源 EXE。

`Profile` 字段：

- `schema_version`：目前为 1，未知版本拒绝。
- `id`、`name`、`process_names`：稳定 ID、显示名称、关联的进程文件名列表。
- `source_sha256`、`source_version`：来源样本指纹和文字版本。
- `features`：修改项数组。

`Feature` 字段：`id`、`name`、`name_en`、`group`、`description`、`input`。

`input` 使用标签联合：

```json
{"kind":"toggle"}
{"kind":"integer","default":9999999,"min":1,"max":2147483647,"one_shot":false}
{"kind":"float","default":1.0,"min":0.01,"max":1000.0}
```

`one_shot=true` 用于 13 项属性编辑，仅显示「应用」按钮，不进入持续启用集合。`Session::active` 存放持续项，`Session::applied` 记录一次性写入结果，数值传输使用 f64，执行时按明确类型转为 i32/f32。才能和友情输入额外检查缩放后的整数溢出。UI 数值范围仅表示后端可表示范围，不保证所有数值都符合游戏规则。原样本热键未注册为全局热键，避免与现有快捷键功能冲突。

读取配置限制 2 MiB、256 个修改项，校验进程名、唯一 ID、数值范围和禁止的速度功能。内置配置优先匹配。外部多个配置匹配同名进程时报告冲突；目前不提供配置选择 UI。输入值只在当前会话保留，重绑/重启回到默认值。

## 执行与生命周期

目标身份为 PID + 进程创建时间 + 绑定代数。重新申请修改权限后再次核对创建时间，并核对主模块名称和 x64 PE 头。游戏更新当前依赖唯一 AOB 匹配和预期原字节检查，尚无经实测建立的游戏版本指纹矩阵。

扫描仅在主模块可执行节区内进行，分块读取并检查取消信号；扫描结果必须唯一，零匹配、多匹配和读取失败均停止。后台任务不持有主 UI 全局锁。

每次启用先检查现有的已知反作弊进程提示；发现命中或检查失败时不执行。这个检查仍是系统范围的有限进程名检查，不是游戏环境的完整证明。

代码替换会临时暂停目标进程，检查各线程指令指针不在修改区域，核对原字节，写入后读回并刷新指令缓存，恢复页面保护和临时暂停。补丁跨页时拒绝。恢复前核对当前字节，避免盲目覆盖其他修改。

金钱/点数以及战斗、伤害、物品、奖励、友情等按组共用钩子和独立参数，各自关闭不会卸载仍被同组其他项使用的钩子。代码页 RX，参数页 RW；同组全部停用时恢复游戏原代码。属性捕获钩子由停用全部/重绑/退出清理；重新安装会清空旧捕获。失败时保留恢复记录，界面不把尚未确认的操作标为已启用。

已分配的钩子区域为每组 8 KiB，同一绑定会话最多 12 组（96 KiB）。停用后保留至游戏退出，由系统回收，避免释放仍可能被引用的远程区域。同一会话重新启用复用分配；反复解除绑定再重新启用会产生新的分配。后续可以在完整线程和调用栈验证后实现回收，不能只在恢复入口跳转后立即释放。

## 属性字段还原证据

23 段明文脚本不足以覆盖属性写入。本轮额外静态反汇编来源样本的原生编辑回调（RVA `0x53960`），结合功能标识引用确定以下对象内偏移：

| 输入 | 偏移 | 写入类型 |
| --- | --- | --- |
| 等级 / 经验 | `0x68` / `0x6c` | i32 |
| 当前 HP / SP | `0x74` / `0x78` | i32 |
| 最大 HP / SP 加成 | `0xb4` / `0xb8` | i32 |
| 攻击 / 防御 / 智力 / 精神 / 速度加成 | `0xbc` / `0xc0` / `0xc4` / `0xc8` / `0xcc` | i32；速度属性不是移动或游戏加速 |
| 才能 | `0x104` 和 `0x108` | 两处均为输入 × 1000 的 i32 |
| 友情 | `0x144` | 输入 × 100 转为 f32 |

捕获钩子读取对象 `+0x04` 的 ID；应用前重新核对。奖励及属性捕获另有独立布局特征检查。`s1.2` / `s2.1` 在专用适配中转为对应长度的通配字节，从匹配的原指令中保留实际位移/寄存器编码；整段被替换指令必须完整解码、无分支且无 RIP 相对寻址。未实现通用扩展语法解析。样本中的属性区域扫描备选形式依赖 `DigimonStats` 符号，当前仍要求主模块特征唯一匹配；遇到多匹配会拒绝，需按实际游戏补充定位证据。

本地复核工具为 `dist/analyze_trainer_callbacks.py`，输出 `dist/trainer-callback-disassembly.txt`；仅静态读取 EXE。应用不依赖这些研究文件或来源修改器进程。

## 测试与继续开发

```powershell
cargo test
# 需要用户提供的 dist 中样本；仅静态读取
cargo test sample_static_import -- --ignored
cargo build --release
```

测试覆盖：40 项能力及排除速度项、输入范围、配置保存/重载、已知样本指纹与变更拒绝、AOB 多匹配拒绝、全部直接补丁和所有新增分组的启停/恢复、全部指令变体的真实机器码执行、小数倍率、共享参数隔离、整数溢出保护、七类物品路由、13 项属性写入与对象失效拒绝、首次应用和重启捕获清空。另有金钱/点数跨进程真实钩子执行、线程检查和原字节恢复测试。所有执行测试仅使用测试程序自己分配的数据或启动的子进程，不修改真实游戏。

Debug 截图：`SLACKINPUT_UI_SNAPSHOT` 指定输出路径，`SLACKINPUT_UI_TRAINER=1` 打开修改器预览；`SLACKINPUT_UI_SCROLL_BOTTOM=1` 检查列表底部，`SLACKINPUT_UI_TRAINER_FILTER=金钱` 检查数值行，`SLACKINPUT_UI_TRAINER_ACTIVE=1` 显示明确标注的预览启用状态。预览不执行修改。`SLACKINPUT_UI_LANGUAGE=en` 可检查英文布局。

建议后续按顺序继续：

1. 使用实际游戏版本验证这 40 项的场景触发、恢复、重启与版本不匹配，记录 EXE 指纹；不要把测试进程通过等同于游戏通过。
2. 根据真实游戏的不匹配报告补充特征及属性区域定位，建立游戏版本验证矩阵；不得通过取消唯一匹配校验来绕过不匹配。
3. 为静态导入器实现 PE 资源/字符串/脚本块解析、格式探测、大小/数量边界、未知语法报告，保留来源偏移，禁止导入时执行脚本。
4. 再接入导入按钮：选择文件 → 后台分析 → 查看功能和适配报告 → 确认进程关联 → 保存配置 → 刷新当前绑定。补充同名匹配冲突和已有 ID 更新流程。
5. 如扩展通用脚本执行，需要独立评估汇编、Lua、外部依赖及回滚模型，不能把样本文本直接交给任意执行器。

程序中统一使用“修改器”名称。用户原始文件及本地静态取证数据不作为产品文案或发布资源。


## 0.7.2 界面迁移

修改器已从游戏页入口与独立 viewport 迁入主窗口第二个页签。页签顺序为游戏、修改器、按键宏、快捷键、设置。主窗口保持 480×560，最小 440×480；TrainerUi::show 接收父 Ui，使用父页签滚动区，移除旧大窗口尺寸和功能列表嵌套滚动。

配置管理默认折叠，导入预览/删除确认时展开显示；搜索独占一行，名称/状态与数值/按钮分行，操作区使用可换行布局。执行错误和清理提示位于功能列表之前。切页保留修改状态，退出清理未完成时切到修改器页，继续使用原 worker 的停用/恢复流程。

截图设置 SLACKINPUT_UI_TRAINER 时在正常主窗口尺寸中预览修改器；SLACKINPUT_UI_TAB 可显式覆盖：游戏 0、修改器 1、按键宏 2、快捷键 3、设置 4。
