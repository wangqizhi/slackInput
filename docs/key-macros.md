# 按键宏技术说明（v0.7.1）

## 使用方式

打开独立的「按键宏」页签，点击「添加宏」，填写名称和触发键，勾选启用，编辑步骤后点击「保存并应用」。本页保存独立于设置页的通用配置保存。

- 按键映射：一次执行、一个步骤，例如 F8 → Space。
- 组合按键：步骤内用 `+` 表示同时按下，例如 `Ctrl+Shift+Q`；不同步骤顺序执行，可添加、删除或上移步骤。
- 按键连发：把次数改为所需次数，例如 Space、按住 40 ms、间隔 100 ms、次数 20。
- 每个步骤按顺序按下组合键，保持指定时长，再逆序释放，等待间隔后继续。最后一步的间隔也计入每次循环。
- 松开触发键及其修饰键后开始执行；长按触发键不会自动重复。支持单键或 Ctrl/Alt/Shift/Win 与一个普通键的组合。
- 「停止全部」取消当前执行和等待松键的任务；之后可以重新按触发键运行。编辑、删除和禁用需要保存才能生效。

## 文件格式

文件位于 `%APPDATA%\SlackInput\macros.json`（与通用配置使用同一数据目录，可在设置页打开）。旧版本没有此文件时启动为空列表。手工修改后重启加载。

```json
{
  "version": 1,
  "macros": [
    {
      "name": "连续跳跃",
      "enabled": true,
      "trigger": "F8",
      "repeats": 20,
      "steps": [
        { "keys": "Space", "hold_ms": 40, "delay_ms": 100 }
      ]
    }
  ]
}
```

格式版本与应用版本独立。最多 64 个宏、每宏 128 步、1–10000 次；按住时长 1–60000 ms，间隔 0–60000 ms。支持 A–Z、0–9、F1–F24、方向键及已有快捷键解析器支持的常见导航键；不支持鼠标、手柄触发、任意多个普通键同时按下或无限循环。

未知字段、未知版本、错误键名、空步骤、超限值和重复启用触发键均拒绝。禁用宏也必须具有合法结构。加载失败在宏页显示错误，不自动覆盖损坏文件；用户明确保存才替换文件。

## 架构与运行规则

`src/macros.rs` 包含 serde 数据结构、校验、Editor 页面、热键注册线程与执行器。`src/main.rs` 将其放入 MapperApp，追加第四个页签，复用按键解析、INPUT 构造及通用捕获/功能锁状态。0.7.2 页签索引为游戏 0、修改器 1、按键宏 2、快捷键 3、设置 4，截图工具使用新索引。

同一工作线程通过 RegisterHotKey + MOD_NOREPEAT 注册并消费 WM_HOTKEY。保存通过通道提交配置，先取消运行，再切换注册；注册失败或写盘失败尝试恢复旧注册，界面显示失败。文件先写同目录临时文件，再 rename 替换，避免直接截断旧文件。极端情况下旧热键可能被其他程序抢占，恢复失败会显示全局状态错误。

执行器通过 SendInput 按下/释放，等待每 5 ms 检查取消代数和全局许可。保存、停止、正常关闭触发取消；关闭输入捕获或反作弊功能锁生效也终止运行。终止路径释放当前步骤全部键；SendInput 失败显示状态，不继续后续步骤。线程退出注销宏热键。

宏串行执行，不堆积任务，执行过程中收到的热键消息在结束后丢弃。输出与任一启用宏触发键相同会在校验时拒绝；输出与当前通用快捷键触发键相同在执行前拒绝，以避免递归或误切桌面。多个宏在开始执行前同时到达时，只保留最后一个待触发任务。

## 行为边界

这是全局热键触发的输出宏，不是底层键盘重映射驱动，不提供源按键按下/松开的透传转换。热键直接触发的宏输出发送给当时的前台窗口；手动运行/继续会激活已绑定游戏，且手动运行期间切离游戏会自动暂停。Windows 保留或其他应用占用的热键无法注册。输入注入受到 Windows 权限等级和目标应用输入实现限制。

时间是软件调度间隔，不保证毫秒级实时精度。热键注册独立于捕获许可，关闭捕获后不执行宏，但已注册触发键仍由系统保留。正常退出会取消；强制结束进程不能保证释放输入。

## 验证

`cargo test --quiet`：覆盖配置往返、无效组合键、重复触发、空步骤、时间边界及项目原有测试。发布前还应在真实目标游戏验证输入兼容性。手工验收：F8 → Space；Ctrl+Alt+Q → 两步组合键；20 次连发；长步骤期间停止；保存重启；两个宏触发冲突；通用快捷键冲突；关闭捕获；输入注入权限不足。

## 0.7.1：录制功能

点击「录制新宏」后有 3 秒准备时间，可切到游戏窗口。倒计时结束前请松开所有按键。录制期间记录全局键盘，普通按键照常传给前台应用；请勿输入密码等隐私内容。按 F12（松开后结束）或页面上的「结束录制」生成新的禁用宏草稿；F12 专用于结束，不进入步骤，也不传给游戏。若需要将 F12 用作输出，可结束录制后手工编辑。

记录顺序组合键、主键按住时长和主键释放到下一步按下之间的间隔，自动忽略操作系统长按重复消息。首步前等待不保存，末步间隔为 0，可手工修改。结果保持 JSON version 1 兼容，先检查触发键、步骤、次数，再勾选启用并「保存并应用」。不会覆盖已有宏或自动写入磁盘。

当前步骤模型是「修饰键 + 一个普通键」，因此多个普通键重叠、按住主键时改变修饰键、不支持的键、未松开主键就结束、时间/数量超限会拒绝本次录制，而非静默丢失按键。先按修饰键、再按主键，先松主键、最后松修饰键；Shift/Ctrl 单独按下不生成步骤。鼠标、手柄和输入法文字不属于录制内容。

最长 5 分钟、最多 128 步，单次按住/间隔不超过 60 秒。取消、切换应用内页签、关闭捕获、反作弊锁定或退出将结束并丢弃录制；切到外部游戏窗口不会取消。F12 是后台可用的结束键，建议按 F12 后再切回工具，避免把切窗口动作录进宏。

`src/macro_recording.rs` 使用临时 WH_KEYBOARD_LL 钩子及独立消息线程。钩子只投递带单调时间戳的虚拟键事件，忽略 LLKHF_INJECTED，通过有界非阻塞通道交给步骤构建器；结束后卸载钩子。Windows 钩子回调必须及时返回，超时可能被系统静默移除，因此仍需用户检查草稿完整性。[Microsoft：LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)、[KBDLLHOOKSTRUCT 注入标志](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-kbdllhookstruct)

录制前取消当前宏，暂时注销宏热键和通用键盘触发键，并阻止 Guide 映射。结束后恢复上次已应用配置，不把其他未保存编辑应用到运行时。恢复冲突时显示错误。记录只在内存中，不上传、不写原始事件日志。

## 0.7.1：反作弊核实

0.7.0 已通过 `allowed()` 在接收热键、等待触发键松开、执行每一步及等待时检查 `features_locked()`；锁生效后不启动新宏，并释放当前步骤按键。0.7.1 新增宏页显式锁定提示和录制门控，录制线程自身也检查许可，不仅依赖 UI 刷新。

现有检测仅在有效绑定游戏时约每 2 秒扫描已知名称，锁只属于当前绑定会话。实际反作弊进程出现到被扫描发现存在延迟；未绑定、未知反作弊或单纯扫描失败并不等同于已检测命中。本版没有扩大检测名单或改为全系统无条件锁定。

自动化测试覆盖步骤时间、组合键、重复消息过滤、普通键重叠/未释放拒绝与非法键；真实游戏的钩子接收和录制回放效果仍需实测。


## 0.7.2 游戏按键兼容性修正

宏输入使用 MapVirtualKeyW / MAPVK_VK_TO_VSC_EX 生成扫描码，设置 KEYEVENTF_SCANCODE，E0 键设置 KEYEVENTF_EXTENDEDKEY，释放复用同样的键编码并加 KEYEVENTF_KEYUP。无映射或 E1 时保留虚拟键回退。原通用桌面快捷键路径保持原行为。[Microsoft：KEYBDINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput)、[MapVirtualKeyW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-mapvirtualkeyw)

这改善输入表达的兼容性，但尚未证明能解决具体游戏无响应。状态栏区分正在执行、停止、发送失败、发送完成；SendInput 成功只证明系统接受输入，不证明游戏角色实际移动。

例如次数 10、W 按住 40 ms、间隔 100 ms 表示十次短按，不是持续前进。验证时建议次数 1、W 按住 2000 ms、间隔 0，保存后切回游戏，确认游戏未暂停且能通过真实 W 移动，再按下并松开 F8。若没有执行提示，排查捕获开关、功能锁和热键注册；若已发送但无响应，排查焦点、游戏权限等级、键位及输入模式。未经真实游戏验证，不把扫描码修正作为已定位根因。


## 手动运行与暂停

每个宏的触发键下方提供「运行 / 暂停」；暂停后显示「继续」。运行使用当前编辑内容的快照，不要求勾选启用或写入配置；仍校验字段、输出冲突、输入捕获与反作弊许可。运行/继续从 UI 点击事件中激活游戏页已绑定进程的可见主窗口；最小化时尝试恢复。未绑定、游戏暂停/退出或 Windows 拒绝激活时提示错误，不开始发送。首次运行先等待目标持续持有前台约 300 ms（约 2 秒预算）再发送第一个按键，避免按键落在游戏尚未就绪的恢复过程中。

后台单实例播放，运行中禁用其他运行按钮和宏删除；编辑不会改变已开始执行的快照。暂停释放当前组合键，保留当前步骤剩余按住时间/间隔和后续循环；继续重新按下并执行剩余时长。暂停期间「停止全部」、保存、录制、退出及许可撤销仍可取消。暂停/继续不是游戏进程的暂停/恢复。

手动任务通过独立通道交给原宏线程；播放状态用原子变量同步，手动播放记录 PID 与绑定代数，解绑、换绑或游戏退出时取消，不复用旧目标。暂停状态检查间隔约 5 ms，软件调度不保证实时精度。


### 自动激活游戏窗口

`BoundProcess::activate_window` 按绑定 PID 枚举可见、无所有者的顶层窗口，选择面积最大的窗口；通过 ShowWindowAsync 恢复最小化窗口，SetForegroundWindow 请求激活。激活是异步的：恢复窗口与繁忙游戏的消息泵都会让前台切换滞后，因此以约 20 ms 间隔轮询核实前台 PID 并按需重试激活，约 1.5 秒内确认成功才开始，期间游戏退出立即报错。失败时保留暂停/未运行状态，不使用模拟 Alt 或跨线程输入绑定强制抢焦点。[Microsoft：SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)

首个按键发送前确认目标持续持有前台（稳定期不改动暂停状态，焦点抖动不会卡住播放）；开始后每个等待片段检查目标会话与前台 PID，失去焦点时释放当前组合键并暂停，回到游戏不会自行恢复，需点击「继续」。仍受 Windows 调度与焦点检查/发送之间的极短竞争窗口限制。热键初次触发保留原前台输入行为；若通过界面继续，则切换为已绑定目标保护。
