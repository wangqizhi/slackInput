# 修改器增删及配置化方案

## 原理与边界

EXE 是导入源，不是插件：只读取字节并交给静态导入器，绝不启动来源程序。第一版接通已验证样本识别器；未知格式明确拒绝，不能靠名称推断地址或脚本。功能名称用于同一游戏配置内的冲突识别（去首尾空白、忽略大小写），内部 ID 继续用于执行器路由。不同游戏不合并。

运行地址由模块实际加载基址与唯一 AOB 匹配计算，不能保存上次运行的绝对地址。扫描特征、相对偏移、原字节、替换字节和属性字段偏移移入 JSON。专用汇编控制流仍属于受控原生适配器；配置不是任意代码执行接口。

## 架构与实现

1. `profile`：版本化数据、名称键、合并预览、逐项覆盖/跳过、批量设置决策、校验、原子落盘。用户配置优先于内置默认，空功能列表合法，保证删除最后一项后不会复活。
2. 导入界面：选择 EXE → 后台限量读取/分析 → 展示来源、警告、新增与同名冲突 → 单项或全部覆盖/跳过 → 确认保存。取消不改变配置。未绑定时允许管理默认游戏，绑定后管理对应配置。
3. 单项删除：行内删除入口、确认名称，后台先恢复会话再保存新配置；恢复失败保持旧配置与恢复记录。共享钩子由现有清理逻辑管理。配置修改后所有功能保持关闭。
4. `worker`：串行执行分析和配置变更，使用绑定代数拒绝过期操作；修改前清理原会话，保存成功后发布新快照。UI 不直接写文件或修改进程。
5. 配置目录为 `%APPDATA%/SlackInput/trainers`。首次加载物化默认配置，后续从文件加载；写临时文件、同步后原子替换。校验失败不回退到默认继续执行。
6. AI 扩展：定义只产出 `ImportDraft` 的提供者接口及请求结构，未来服务返回的数据必须通过同一校验、冲突预览和确认入口；不预置网络请求、密钥或自动启用。AI 不能凭功能名称取得适配能力。

## 验证

覆盖名称规范化、混合覆盖/跳过、全部决策、ID 冲突、单项及最后一项删除、保存重载、损坏配置拒绝、未知 EXE 拒绝，以及配置驱动的原生扫描和恢复。运行现有自建进程测试与编译检查。测试通过不代表真实游戏版本兼容。

## 兼容性

保持现有配置 schema 兼容，通过缺省值迁移新增执行数据。内置游戏的进程身份与已适配功能输入契约仍受校验，允许功能子集及空集合；名称仅决定导入冲突，不改变执行器身份。配置热更新通过结束原会话实现，不在已安装钩子上替换定位数据。

## 已实现的配置与操作说明

默认目录：`%APPDATA%\SlackInput\trainers\digimon-time-stranger-20260709.json`。界面显示实际目录，支持“重新加载配置”（先清理旧会话）。手工编辑后点击重载或重启；运行中的会话不会自行读取变化。旧 schema 1 文件缺少 `execution` 时使用版本化默认因子，下次保存写入完整结构。删除后保留配置文件，空数组表示所有项均已删除；重新导入 EXE 可恢复项目。

默认执行数据位于 `assets/trainers/digimon-execution.json`，首次创建用户配置时序列化至 `execution`：

| 字段 | 含义 |
| --- | --- |
| `address_resolution` | `main_module_unique_aob`：动态模块基址 + 唯一特征定位，不存易失的绝对地址 |
| `groups` | 共享钩子的 AOB、匹配点偏移、原指令模式 |
| `layouts` | 奖励、属性对象布局的独立校验特征 |
| `patches` | 直接补丁与金钱组定位；原字节与替换字节使用十进制字节数组 |
| `stats` | 每个属性的偏移数组、整数缩放、是否写为 f32 |
| `fields` | 战斗、CP、物品、奖励、对象 ID、金钱/点数等对象字段偏移 |
| `limits` | 无限血量、经验、扫描率等固定写入数值 |
| `evolution_offsets` | 清除进化要求时的字段偏移列表 |

JSON 数字使用十进制，例如 `104` 对应 `0x68`；AOB 使用十六进制字节和 `*` 通配。地址算法、分组参数协议、x64 指令生成与寄存器语义仍由原生代码管理。变更因子不等于自动兼容另一款游戏。钩子原指令必须满足现有适配器契约，配置加载拒绝不支持的指令形状、全通配扫描、无效偏移及不匹配补丁长度。

按名称合并时，覆盖同时更新该项相关的执行数据；跳过保留原数据。若共享定位变化会影响跳过的同组项目，拒绝保存并提示同时覆盖；全局共享字段变化则要求全部覆盖。不同名称却占用相同内部 ID 时拒绝，避免两个界面项误用同一个执行状态。

AI 扩展入口为 `AiDraftProvider::propose(AiRequest) -> ImportDraft`，请求携带当前配置和用户指令。当前仅预留接口，没有网络服务或模型依赖。未来接入需对返回草稿执行 `Profile::validate` 并进入同一导入预览流程；新增原生行为仍需适配器开发与验证。

当前 EXE 导入支持已研究的时空异客样本（SHA-256 见开发文档），未知或被修改的 EXE 明确拒绝。文件对话框、限量读取及分析位于工作线程。未绑定也可管理默认配置；导入过程不会执行来源文件，确认保存前不会更改现有功能。

## 本次验证结果

`cargo test`：43 项通过，1 项按默认忽略（依赖本地来源 EXE）。另运行 `cargo test sample_static_import -- --ignored`，本地真实样本静态导入通过。新增测试验证名称混合合并、批量跳过/覆盖、ID 冲突、共享数据冲突、删除与空列表持久化、原子替换、损坏配置拒绝、配置偏移/缩放在测试内存中实际写入。真实游戏效果仍待实测。

工作线程测试另覆盖过期绑定代数拒绝、串行保存、空配置重载。Debug / Release 构建通过，并检查普通列表与导入预览截图。`cargo clippy --all-targets -- -D warnings` 未通过：仓库仍有原有的嵌套条件、范围表达式等样式告警；普通编译和测试通过。
