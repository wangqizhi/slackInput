# 修改器数据导入可行性研究

研究日期：2026-09-18。范围：用户提供的《数码宝贝物语：时空异客》42 项修改器；仅静态读取文件，没有执行修改器、加载其中的 DLL、操作游戏内存或修改应用功能/UI。

本文记录最初的静态研究。后续 v0.5.0 的界面、5 项原生适配、测试结果及导入接口，以[开发交接文档](trainer-development.md)为准。

## 结论

本样本可提取功能数据和部分执行脚本，已完成提取验证；将这些功能交由 SlackInput 独立执行在工程上有可行路径，但尚未完成执行兼容性验证。不能把这一结果推广为任意修改器 EXE 的通用导入能力。

建议以“识别指定格式 → 提取到中间数据 → 明确标记未适配功能 → 按游戏/版本验证执行”的方式推进。如果目标是无需原修改器运行，则需要自己的执行后端或经过评估的兼容引擎，不只是增加文件导入按钮。

具体观察：

- 无限 HP 与无限 SP 共用一个脚本、各自用内部标志控制，不能简单把“关闭一个选项”等同于卸载整段脚本。
- 金钱与超常点数也有共享脚本，且存在不同扫描特征的脚本变体；变体选择规则还需恢复。
- 部分属性编辑脚本只捕获当前数码宝贝地址和标识。42 项功能的全部字段类型、偏移、更新与写入条件不能仅凭 23 段脚本完整还原。
- 可见 `s1.2`、`s2.1` 等特征表达式，以及对 `s1` 等符号的引用，需要确认作者引擎的具体解释规则，不能直接当作标准 CE 语法执行。
- `--money` 一类文本出现在功能定义中。现在只能认定它们是内部标识，不能认定 EXE 支持这些命令行参数。
- 原始文本包含 `<input default=...>`、`<input_set default=...>` 和说明分隔标记，可以提取元数据，但还需核实运行时类型、范围和一次性/持续修改行为。

## 接入路径比较

| 路径 | 可行性判断 | 主要限制 |
| --- | --- | --- |
| 导入功能目录、热键、说明、默认值 | 本样本已证明可提取 | 显示数据不等于功能可执行；应按格式识别，不能任意字符串都当配置 |
| SlackInput 调用原修改器，转发热键 | 可做原型，尚未运行验证 | 仍需原程序；快捷键冲突、权限、输入值传递、启用状态同步均需适配 |
| 从 EXE 提取并由 SlackInput 独立执行 | 本样本有可行路径，工作量较大 | 需要脚本引擎、扩展语法、共享依赖、版本选择和编译代码中的补充逻辑 |
| 支持 Cheat Engine `.CT` | 格式更适合结构化导入 | 支持 XML 解析不等于兼容 Lua、Auto Assembler、自定义类型和外部组件 |
| 任意 Trainer EXE 自动转换 | 不建议承诺 | 作者、框架、编译版本、压缩/混淆和运行时依赖都可能不同 |

CE 官方资料确认：表项可以使用 XML 表达，而修改逻辑可包含 Auto Assembler 和 Lua；并非纯地址列表。参考 [表项 XML 示例](https://wiki.cheatengine.org/index.php?title=Tutorials%3AAuto_Assembler%3AExample_1)、[脚本说明](https://wiki.cheatengine.org/index.php?title=Scripting)、[Auto Assembler 说明](https://cheatengine.org/help/auto-assembler-help.htm)。本样本的语法相似性不证明它由 Cheat Engine 生成，也不证明可以直接用 CE 执行。

## 对现有项目的影响

目前项目只有进程绑定/暂停和有限的反作弊进程提示，没有游戏内存修改或脚本运行后端。前一份游戏数据方案建议从数据字段读写开始、不写代码页；本样本大量使用扫描、分配内存、汇编跳转和恢复原代码，属于明显更大的范围扩展。

如果继续做独立执行，应拆成三个可验证部分：

1. 导入器：限制文件和字段大小，识别文件指纹/格式，保留来源偏移，输出功能元数据、脚本文本、未知依赖，不执行导入内容。
2. 适配层：解析功能与脚本的多对多关系、共享依赖、数值参数、版本变体和特殊组件；不能根据名称自动猜测写入位置。
3. 执行后端：实现已验证语法、地址定位与唯一性检查、启用/停用和共享资源生命周期；游戏退出、切换绑定、部分启用失败时正确清理。未适配项明确标记为不可执行。

## 推荐下一步，不涉及 UI

先针对这个文件做专用导入原型，导出 42 项结构化清单及脚本依赖报告；选一个简单功能做完整适配验证。第一轮先用自建测试进程验证解析、启停和恢复，再在明确的游戏版本验证实际效果。

完成标准应为：同一功能多次启停和游戏重启后表现正确，共享脚本不互相误卸载，版本不匹配能够停止操作，故障不会留下错误的“已启用”状态。达到这个标准后，再决定扩大到更多功能或兼容其他修改器格式。

目前不能给出完整移植工期：尚未恢复所有回调、扩展扫描语法和版本选择逻辑，也未拿到实际运行游戏的版本身份。数据提取已验证，独立执行及游戏兼容性未验证。
